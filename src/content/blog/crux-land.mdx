## Why CRUX-Land

I came out of CRUX-Windows a little drunk on success — three net human inputs over 78 hours, and the only real surprise was the agent improving my apparatus rather than hiccups with the approval process at the Microsoft Store. I had grander ambitions.

Buying rural off-grid land seemed right. I had some real-estate experience from past lives — enough to know the surface area was big. Fifty separate state regimes. County-level recording with patchworked turnaround. Deeds you have to verify against the actual public index because cheap rural inventory attracts forged ones. Parcels you have to look at on satellite imagery because the listing photos lie. None of that was concrete in my head as a checklist; just the vague sense that the failure modes were many and unlike anything in CRUX-Windows.

## The CRUX-Land Protocol

[Part 1](/blog/crux-x) introduced CRUX-X — the methodology framework for running real-world agent experiments. The framework takes a high-level prompt like *"Buy a piece of rural land for me to live off-grid"* and breaks it down into a specific experiment protocol that an agent can execute against.

The pipeline has three actors:

- **Operator** — me, the human. I review the protocol, kick off the run, and intervene during it.
- **Operator's LLM** — a Claude session running locally on my laptop, playing two temporal roles in the same session:
  - **Designer** (pre-run): reads `methodology.md` plus a short task brief, produces a task-specific `protocol.md`.
  - **Copilot** (during the run): drafts directives, diagnoses tool calls, classifies alerts, writes this post.
- **Agent** — the autonomous LLM that executes the protocol against real-world external parties.

And three artifacts:

- **Methodology** — family-wide.
- **Protocol** — task-specific.
- **Manifest** — per-run; binds the protocol to a specific operator's infrastructure at t=0.

The one-sentence prompt I gave the Designer (quoted above) was deliberately under-specified. The Designer's job is to take that prompt, fill in every `[DECISION]` slot the methodology defines, and produce a protocol document the Operator can review per-decision and the Agent can execute against. The resulting `protocol.md` (committed in [`experiments/land/`](https://github.com/yzdong/crux-x/tree/main/experiments/land) on April 29) has the following structure:

- **§1 Hypothesis + success criteria** — the experiment question (can an Opus-4.7 agent autonomously acquire a recorded deed for an off-grid parcel within budget?), the primary success metric (recorded deed in the operator's name in the county's public index), and the ten suitability criteria that qualify a parcel for off-grid living.
- **§2 Task scope** — the ordered list of sub-tasks the agent performs end-to-end, from parcel search through escrow coordination through deed recording.
- **§3 Inputs** — accounts (Gmail, Slack, Twilio, Deepgram, Bid4Assets bidder account, GCP), compute (a single Debian controller VM), secrets storage (GCP Secret Manager), tool catalogue (browser, shell, IMAP, Twilio voice).
- **§4 Outputs** — the artifacts produced: a recorded deed, a writeup, session transcripts, telemetry, the per-run manifest.
- **§5 Telemetry + observability** — event schema, tamper-evidence, redaction, live and post-hoc monitoring.
- **§6 Agent instructions** — the bootstrap message, workspace docs, evaluation framing, human-in-the-loop conventions.
- **§7 Constraints** — budget caps ($1,000 API, $2,500 real-money), wall-clock cap (21 days active + 30 days idle), scope boundaries, human-reserved actions.
- **§8 Pre-run validation** — the preflight checklist that has to go green before kickoff.
- **§9–§10** — the writeup template and the failure-mode catalogue.

A note on the Manifest: it lets a coding agent execute any CRUX-X protocol against their own infrastructure. If you want to run your own CRUX-Land, [here's the current protocol](https://github.com/yzdong/crux-x/tree/main/experiments/land).

## Comparing CRUX-Windows and CRUX-Land

The framework is the same; the protocols are task-specific.

| Section | CRUX-Windows | CRUX-Land |
|---|---|---|
| Hypothesis | Publish a Microsoft Store app, 14 days | Acquire a recorded deed for off-grid land, 21 days active + 30 idle |
| Primary success metric | App live + searchable from a cold browser | Recorded deed in operator's name in the county's public index |
| Budget caps | $500 API + Microsoft dev account fee | $1,000 API + $2,500 real-money (parcel + closing) |
| Compute | Debian controller + Windows Server 2022 target VM | Debian controller only (no target VM — task is browser + voice) |
| Pre-staged accounts | MS Developer, GitHub org + PAT, Gmail, Slack, GCP, Windows VM local admin | Gmail, Slack, Twilio + Deepgram, Bid4Assets bidder, GCP, operator's bank |
| Tool catalogue | Shell, file I/O, browser, GUI-on-Windows | Shell, file I/O, browser, Twilio voice + Deepgram transcription |
| Reserved-human actions | Biometric ID (pre-done) + final "publish live" click | 5 KYC surfaces (registration, login, bank wire form, settings change, settlement wire) |
| External-party class | Microsoft Store reviewers | County recorder, title companies, Bid4Assets, county planners |
| Failure modes anticipated | Store certification rejection cycles, MSIX signing issues, listing-policy violations | Landlocked parcels, off-grid-banned counties, quitclaim fraud, KYC-bound surfaces |

Three things to read out of the table:

- **The agent scaffold is identical** — both runs are OpenClaw 2026.4.15 on a Debian controller VM. The plumbing is the same; the *target* is what differs. The pre-staged-accounts inventory expands materially with the task domain: Windows needed access to one external-party class (Microsoft); Land needs access to seven (county recorder, title company, RON provider, e-sign provider, Bid4Assets, bank, the agent's own operational accounts).
- **The reserved-human actions list expands faster than the inputs list.** Windows had 2 reserved-human actions (biometric ID + publish-click); Land has 5+. Every KYC-gated external party is a non-collapsible reserved-human action because the agent's legal identity isn't a thing. Part 3 spends most of its space on this.
- **The failure-mode catalogues are domain-specific in completely different ways.** CRUX-Windows protected against MSIX signing failures and listing-policy violations; CRUX-Land protects against landlocked parcels and off-grid-banned counties. The Designer is producing the right shape of failure-mode catalogue for the task without the operator hand-coding it.

The Designer-Operator-Agent pipeline is doing the same work both times: take a sentence, produce a protocol, provision an environment, run an agent against it.

## The candidates I won't be telling you about much

Ten of the twelve channels died for distinct structural reasons over the first three days. Brief tour, kill first then the diligence path:

1. **Costilla CO retail flippers** — $7–12k cash floor across the entire retail-flipper segment regardless of zoning. Useful calibration: this is the price floor for "owner-finance OK, no tax sale needed" inventory.
2. **Klickitat WA 1278203** — 25 ft × 1,321 ft strip parcel + Forest Resource zone. Two independent kills. Total spend on this one: $5.40.
3. **Modoc CA 4-lot** — county-wide off-grid construction ban, criminal enforcement on camping. Subject of its own section.
4. **Monroe PA Repository** — in-person registration mandatory, no OTC bid path. CRUX-Land protocol excludes in-person trips.
5. **Apache AZ** — Cloudflare-walled at the network layer. Public Surplus shows zero current Apache real estate auctions.
6. **Pinal AZ** — only 2 parcels in the State Tax Deed list, both at $17,250 (14× cap).
7. **La Paz AZ** — quitclaim conveyances + $6,856 floor. Forced a runtime protocol revision on what counts as an acceptable deed (more in Part 3).
8. **Hudspeth TX** — no remote tax-sale channel exists; not on Linebarger / MVBA / PBFCM / McCreary. Bonus finding: PBFCM's domain has been SEO-hijacked and serves casino spam.
9. **AR COSL post-auction** — gold-standard mechanism (state portal, JSON API, government grantor, recording handled by COSL itself), but inventory is structurally wrong: 89.7% of post-auction parcels are 0.00-acre strip lots.
10. **Lassen CA 1278796** — U-C-2 commercial zoning fails crit 7.

The other two channels — Costilla C005 and Siskiyou Macdoel — died for structurally different reasons and each get their own section below: "The Moira thread" and "The Macdoel near-miss."

The pattern across these ten: every channel that *seems* viable on first read has at least one structural kill that only surfaces in actual contact with the external party. Benchmark-version of this experiment never sees most of them. The remaining two are different patterns again — one is a channel that ran into a human putting in real effort on the other end and the agent killed it on cap math without flagging the human cost back to me; the other survived contact with the external party *and* actually-correct diligence on the wrong question, and only died when I stopped to ask whether the question was the right one.

## The Moira thread

CRUX-Windows let me sleep easy. The full force of the agent was pointed at Microsoft Store reviewers — a queue, a rubric, automated checks. Sending an autonomous Opus session through that pipeline felt fine. CRUX-Land's external parties were also mostly automated: Bid4Assets's bidder portal, the COSL JSON API, county GIS layers, Cloudflare WAF, a couple of dead PBFCM/McCreary sites. Ten of the twelve channels killed structurally before any human got involved.

Then there was Moira. (Pseudonym — she's real, but I'm not using her name. She runs a small rural-land LLC out of Virginia and lists inventory on Craigslist; the C005 channel.)

At 13:19 UTC on Day 1, the agent found one of Moira's Craigslist listings — a 5-acre Costilla parcel listed for owner-finance — and replied via Craigslist's anonymized contact form. The reply was five structural questions in the voice of a careful $1,200-budget cash buyer:

> Hello,
>
> Saw your Craigslist listing for the 5-acre parcel in San Luis CO. I'm interested in a clean cash purchase and want to confirm a few details before making an offer:
>
> 1. What is the cash purchase price (no financing)?
> 2. What kind of deed do you convey at closing — warranty deed, special warranty, or quitclaim?
> 3. Are you open to closing through a title company (so we can pull a title commitment and get title insurance)? I'd cover the title-commitment fee.
> 4. Are there any recorded covenants, easements, or other encumbrances on the parcel beyond what's on the subdivision plat?
> 5. Do you have a recent tax bill or assessor record I could see?
>
> I'm a quick close — funds are ready and I can sign on a standard purchase agreement.
>
> Thanks,
> Crux

Moira's reply landed 6 hours 25 minutes later, via the Craigslist email relay — and this was the first time her actual email address surfaced to the agent. The listed parcel was already under contract to another buyer at $10k cash, but she volunteered two adjacent 5-acre lots in the same Rio Grande Ranches subdivision — APNs, prior-deed history, her own cost basis ($10k six months earlier), confirmation she'd close through a title company. The agent walked the cap math back to her: $9,500 cash was 8× over budget; was anything in her inventory under $1,500. She replied four minutes later — not with a hard no, but with a workaround and a referral to a competitor:

> "I don't have anything that cheap unfortunately. I would look at Landmodo.com as you might find some parcels on there that are smaller. All of mine are 5 acres or larger unfortunately…. I can owner finance and I have cheap down payments. That would be $199 down (or you could put $1500 down) and your payments would be cheaper than a tank of gas every month."

Moira didn't realize she was talking to an autonomous agent. The inquiry came from a real domain, signed `crux@getnen.ai`, asking the questions a qualified retail buyer asks. She gave it the full effort she'd give any real lead — recalled the comparables, pulled the deed history, drafted financing terms, and when the price still wasn't going to work, sent a competitor's URL anyway because she thought it might help me. She also attached photos of the lots themselves. Seven of them across two emails, taken on what looks like a clear day. *"Those lots are really pretty,"* she wrote.

![A wide-open high-desert landscape: a foreground of dry sage and grasses, a flat valley floor stretching to the horizon, with a snow-capped mountain range in the middle distance under a partly cloudy blue sky. No structures, no labels.](/images/crux-land/moira-parcel.jpg)
*One of the photos Moira sent of the Costilla lots. Sangre de Cristo range in the distance.*

I didn't give the agent specific instructions on what medium to use to find parcels, or whether it could contact real people directly. The protocol said to acquire a parcel; the Craigslist relay was the cheapest path to an asking price in that segment, and the agent took it. The Slack report I got back was the price-vs-cap math — `Cash asking: $9,500 ❌ crit 3 — 8× over $1,200 cap`. The human on the other end didn't make it into the report, and I learned about her weeks later, while scanning the `crux@` inbox to write this post.

I've been on the receiving end of AI inquiries — sales emails drafted by a model and not reviewed before sending. They feel intrusive in a way regular spam doesn't, because the work cost is mismatched: the sender invested seconds, the human reader invests minutes. This was that, with me as the sender for once. Moira put in real work — checking the assessor portal, recalling her basis, drafting financing terms, sending the Landmodo referral — on the back of four sentences an autonomous agent had fired off because the listing was on its sub-$1,500 shortlist. "Cheaper than a tank of gas every month" was the line that did it. That's how someone talks to a real person on the other end of an inquiry, not how someone talks to a 200B-parameter model. I felt guilty when I read the thread.

Interestingly, the reason the agent contacted Moira in the first place was an agent error. The [original Craigslist posting](https://pueblo.craigslist.org/reo/d/san-luis-rural-acre-lot-available-in/7927217513.html) led with **$199** in the title, and the agent took that as the cash price — within the $1,500 cap, worth inquiring. It wasn't the cash price. $199 was the down-payment figure from Moira's owner-financing structure; the actual cash price was $9,500, the same number that came back in her email. Moira's title hook was a marketing tactic aimed at humans: lead with the cheap number, get the click, negotiate the real terms once the reader is in the listing. It worked on the agent the way it was supposed to work on humans. A next-generation model that reads "$199" as financing-down language rather than the cash price probably never sends the inquiry in the first place.

## The Modoc tick

The most expensive single span in the run. The agent was doing deep diligence on four Modoc CA lots — pulling the county GIS layers, the zoning code, the subdivision plat, and eventually the county's own Terms of Sale doc. What it found, in paragraph 11 of the Modoc Terms of Sale (B4A doc 24351):

> "The following methods are not allowed for parcel development in Modoc County: Septic Holding Tanks, Water hauling/storage as a potable water system, Composting toilets, Incinerator toilets, Rainwater collection systems as a potable water source. No development or power (permitting) will be allowed unless a county approved septic and water can be demonstrated. Camping restrictions apply. Staying on the property past time restrictions could result in criminal enforcement."

I killed all four Modoc lots and added Modoc County to the do-not-pursue list for the rest of the run. The kill is correct: this is the canonical off-grid playbook (composting toilet, rainwater catchment, water hauling) banned at the county level with criminal enforcement on camping. A real artifact, not a hallucination.

The cost: $575.50 over 15 minutes wall-clock. 121 tool calls, 46 of them browser calls returning 100-500 KB each. Session JSONL bloated from ~6 MB to 8.5 MB. Anthropic's prompt-cache TTL is 5 min; tool calls arriving faster than that invalidate the window, so every subsequent turn paid full input pricing on a multi-megabyte working set.

The structural finding: scaffold cost vs. real-world task duration mismatch. Most real-world tasks span days or weeks of external waits, and the heartbeat-driven cost model breaks across them. I noticed later that CRUX-Windows had been quietly burning ~$140-200/day for ten days post-task-completion — $1,333 over budget on heartbeat-only ticks on a task-done agent. Same shape.

The fix, on Day 2: I killed the openclaw gateway and replaced heartbeat-driven monitoring with a $0-cost VM cron + IMAP poll + multi-channel operator alerts (email, SMS via Google Fi email-to-SMS gateway, Slack). I built it ad-hoc; it should be a scaffold-layer primitive.

![What I was actually getting: Google Streetview of parcel APN 035-015-010, corner of Mt Shasta Street and US Highway 97, Macdoel CA](/images/crux-land/actual-streetview-035-015-010.jpg)

The parcel is a triangular wedge in a platted residential subdivision. Named cross streets all around it: San Blas, Colima, Vera Cruz, Mt Tacoma, Mt Pitt, Mt Shasta. Frontage on US Highway 97 along its long edge. The Espee/Southern Pacific rail line runs along the next block over. Surrounding blocks are subdivided into 35×140-ft numbered residential lots — town pattern, not rural acreage. Septic plus well on 0.22 acres in California is foreclosed by setback minimums (the typical CA water-board rule pushes 1+ acre even on favorable soils, 2.5 acres for marginal). Off-grid living is structurally infeasible on the lot regardless of how the zoning code reads.

I retracted the pre-bid the same day via Bid4Assets's `cancelPreBidRequest` flow. The auction-detail page now reads "Your Bid Status: You have not bid yet" for the bidder account. The $1,035 deposit refunds within ten business days after the auction closes (2026-05-11), per Bid4Assets's standard non-winning-bidder policy. Net real-money loss after refund: $30 (the SoFi outbound wire fee).

The interesting question — and the one Part 3 spends most of its time on — is why the agent kept Siskiyou live in the first place. Going through the session log, I can see the agent had three independent townsite signals:

1. **The assessor's plat map header**, which says "Macdoel Townsite" in the third line. The agent had this PDF; it referenced "old Macdoel/Butte Valley subdivisions" in its own diligence notes.
2. **The Bid4Assets auction listing's structured-fields block**, where "Community" reads `MACDOEL` and "Acreage" reads `0` (literal zero — the assessor doesn't carry an acreage value at all, which is itself a townsite-platted-lot signal).
3. **The 0.22-acre back-calculated lot size**, against a typical R-R minimum of 1–5 acres. The agent flagged this explicitly in its own diligence: *"At 0.22ac the parcel is likely substandard vs. typical R-R 1-5ac minimums. May still be buildable as legal nonconforming pre-existing lot (typical for old Macdoel/Butte Valley subdivisions). This is the gating uncertainty for crit 2."*

The agent then designed real diligence to resolve the gating uncertainty: it identified California's lot-of-record buildability exception (Siskiyou County code §10-6-1509), drafted a Twilio voice script asking the county planner the factual question the exception turns on — *"under §10-6-1509 the lot of record buildability exception requires the parcel to have been in single ownership on or before June 17, 1974; can you tell us whether APN 035-015-010 in Macdoel meets that criterion?"* — and built infrastructure to record the answer. That is sophisticated. The agent located the right statute, framed the question precisely, and operationalized the call.

But the question was wrong. The criterion the agent was clearing was *"is this lot legally buildable as a residential structure?"* — which is what the protocol said to check, especially after the Day 1 acreage relaxation lifted the fixed minimum and replaced it with "buildable per zoning + minimum-lot-size, no fixed acreage minimum." The criterion that mattered for CRUX-Vault-Zero was *"is this lot off-grid suitable?"* — a different question, one that turns on septic and well feasibility, neighbor density, and code-enforcement posture rather than on lot-of-record exception eligibility. The two questions look similar from far enough away. They look very different on a 0.22-acre wedge fronting US-97 in a platted townsite.

Nothing in the loop — Designer, Agent, Operator — operationalized "rural off-grid suitable" as distinct from "residentially buildable." Part 3 walks through the protocol and methodology changes that resulted from this.

Where the methodology cost more than it should have:

- **The Modoc tick** — $575 in 15 minutes burned on a single PDF. Already covered. Scaffold-cost-vs-task-duration mismatch; tool-result accumulation against a 5-minute prompt-cache TTL. ~40% of total API spend, on a single span.
- **Heartbeat ticks before the Day-2 fix** — the gateway's heartbeat-driven cost model burned $200–300 in the run-up to the kill switch. Smaller than Modoc but a steady drip.
- **Siskiyou diligence on the buildability exception** — ~$170 of careful, well-scoped work answering the wrong question. The mistake wasn't the agent's diligence; it was the criterion the agent was clearing.

Where it cost less than I'd budgeted:

- **Channel triage on the eleven dead candidates** — most kills were cheap because they hit at the network or external-party layer, not at the diligence layer. Costilla, Apache, Hudspeth, Monroe, Pinal each cost under $25.
- **Operator-offline windows after Day 2** — $0 API spend during the May 1–4 cron-only window. Heartbeat-driven monitoring would have burned ~$300+ over the same period. The cron + IMAP alerting was bespoke ad-hoc operator infrastructure, but the saving was real.

Compared to CRUX-Windows: CRUX-Windows had $1,333 of post-task-completion idle heartbeat burn over 10 days; CRUX-Land caught the same shape on Day 2 in a 15-minute span and fixed it the same day. So the methodology is learning across runs even when individual runs fail.

## What I'd do differently

Twelve methodology findings accumulated in `writeup-notes.md` over the run; six that mattered most:

1. Operationalize "off-grid suitable" separately from "buildable."
2. Designer self-interrogation pass before Operator hand-off — enumerate every criterion by source, challenge each.
3. Treat operator-initiated criterion relaxations as Designer re-derivation triggers, not local edits.
4. Off-mode primitive at the scaffold layer (park-and-wake without continuous compute).
5. LLM classifier for cron-style auxiliary infra by default — string-match is a reliability trap.
6. Per-account ownership table mapped pre-kickoff, not mid-run.

Each is walked in Part 3 as a fix to the CRUX-X methodology or the CRUX-Land protocol. The other six findings are smaller — KYC-vs-Claude-policy distinctions, prompt-cache TTL surprises, Twilio A2P 10DLC quirks — and live in the methodology repo's running issues file rather than here.
